# Auto Vesta — sim

Симуляция автономной Lada Vesta на Webots + ROS 2 (Humble). Ветка `sim`
содержит только симулятор (мир, модель машины, драйвер, Docker-окружение) —
без железа и остального автопилота.

## Требования

- Docker + Docker Compose (с правами текущего пользователя, см. `docker info`)
- Linux: X11 и `xhost` (пакет `x11-xserver-utils`) для вывода окна Webots, `make`.
- Для полной работы восприятия: Linux `amd64`, NVIDIA GPU, совместимый драйвер
  и `nvidia-container-toolkit`. CPU-проверка зависимостей образа не доказывает,
  что GPU-выполнение или рендеринг Webots работают.
- Модели и чекпойнты находятся вне образа: нужны каталоги, монтируемые как
  `/offroad` и `/models`; ONNX-файлы экспортируются отдельно командой `make onnx`.

## Быстрый старт

```bash
make                          # справка
make image                    # получить публичный образ, если его ещё нет, и проверить
make up                       # поднять контейнер в фоне и зайти в bash
```

По умолчанию используется публичный `ghcr.io/ssskiv/vesta-sim:nav2ai`.
`make image` использует локальный кэш и скачивает образ, только если его нет;
`make pull` явно обновляет выбранный образ из реестра. Для локальной сборки
используйте `make image-build` (инкрементально) или `make rebuild` (с нуля,
без кэша; также очищает `.build`). Локальная сборка выбирается так:

```bash
VESTA_IMAGE=vesta-sim:latest make up
```

Для прямого вызова Compose сначала подключите общий выбор образа в той же
оболочке: `source docker/image.sh`. Для закрепления/отката на проверенный
bootstrap-образ можно указать digest; это опубликованный образ, а не обещание,
что следующий выпуск будет иметь тот же digest:

```bash
VESTA_IMAGE=ghcr.io/ssskiv/vesta-sim@sha256:cf0a98f3e5544443acee5c4e0e95dfdd6349c9d653b931589762435bc56c6524 make up
```

Для обычного запуска используйте `make up` или `make demo` как прежде. Образ
работает на `linux/amd64`; полный стек восприятия требует NVIDIA GPU, драйвер
хоста и NVIDIA Container Toolkit. Проверка CPU-зависимостей не проверяет
фактическое исполнение на GPU или рендеринг. Каталоги моделей и исходников
монтируются отдельно от образа, а сборка ROS workspace выполняется при запуске
и повторно инкрементально. Смена или откат образа не откатывает содержимое
этих монтируемых каталогов и кэшей.

Публикация требует входа издателя в GHCR и безопасного PAT с правами на
публикацию пакетов, а также доступа к Actions и подключения пакета к репозиторию
с видимостью Public. Это требования издателя; потребителям для скачивания
публичного образа вход в GHCR не нужен.

Внутри контейнера воркспейс собирается автоматически при первом запуске
(`colcon build`), затем запустите симуляцию:
```bash
ros2 launch webots_ros2_suv robot.launch.py
```

### Команды `make`

| Команда | Описание |
|---|---|
| `make` | показать справку |
| `make up` | получить выбранный образ, только если его нет, поднять контейнер `vesta_sim` в фоне, дождаться сборки воркспейса и зайти в bash; повторный вызов просто заходит в контейнер |
| `make image` / `make pull` | проверить/получить образ или явно обновить его из реестра |
| `make image-build` | инкрементально собрать локальный `vesta-sim:latest` |
| `make shell` | одноразовый контейнер с bash (удаляется при выходе) |
| `make headless` | то же без графики, только API |
| `make rebuild` | пересобрать локальный `vesta-sim:latest` без кэша и очистить `.build` |
| `make stop` | остановить контейнеры |
| `make attach` / `make exec` | зайти в уже запущенный контейнер (ещё одна оболочка) |
| `make demo` / `make demo-stop` | запустить / остановить демо Nav2 + восприятие (`ARGS="gui:=true barrels_seed:=3"`) |
| `make gpu`, `make check` | показать определённую видеокарту; проверить Docker |

Параметры: `GPU=nvidia\|amd\|intel\|cpu` — задать видеокарту вручную (`make up GPU=amd`), `HEADLESS=1` — без графики,
`CMD="команда"` — выполнить команду в контейнере и выйти.

## Что внутри

- `ros2_ws/src/webots_ros2_suv` — ROS 2 пакет: мир `worlds/robocross.wbt`,
  PROTO-модель машины (`LadaVesta*.proto`), драйвер `vesta_driver.py`,
  launch-файл `launch/robot.launch.py`.
- `models/vesta` — 3D-модель кузова (Blender/OBJ/Collada) и текстуры.
- `docker/` — `Dockerfile` (ROS humble + Webots) и compose-оверлеи по GPU.
- `Makefile` — точка входа для запуска (`make`).
- `oscc`, `ros2_ws/src/ros2cco` — git-подмодули (сторонние зависимости).
  Загружаются командой:
  ```bash
  git submodule update --init --recursive
  ```

## Управление и топики

- `vesta_driver.py` принимает `geometry_msgs/Twist` на `/cmd_vel` (режим
  скорости, подходит для `teleop_twist_keyboard` и Nav2) либо сырые
  throttle/brake команды (режим torque).
- Публикует: `/imu/data`, `/lidar`, `/radar`, `/joint_states`,
  TF `odom -> base_link`.

## Ветка `nav2ai`: восприятие + Nav2

Пакет `ros2_ws/src/offroad_nav2` — стек «стереокамера → три нейросети → облака точек → Nav2 (только вперёд)» для Webots.
Лидара в симуляции нет, препятствия берутся только из камеры. Запуск и всё остальное: `ros2_ws/src/offroad_nav2/docs/LAUNCH_GUIDE.md`.

```bash
make demo                                           # сборка, запуск и ожидание готовности Nav2
```

В этой ветке оставлено только нужное для этого стека: Webots (`webots_ros2_suv`, судья, бочки), `offroad_nav2`, подмодули `oscc` и
`ros2cco`. Autoware, обучение RL, нейро-контроллер и CARLA удалены (остались в истории git, ветки `sim`, `ai`).

## Известные ограничения

У топиков камер (`/stereo_raw/*`) время берется не из симуляции, а из реального мира. Если нужна будет синхронизация, надо будет сделать прослойку, которая будет менять время на время симуляции.  

Поддерживается только Linux. Если будут проблемы - создавайте pull requests.

По любым вопросам к автору репозитория, в профиле контакты есть.

Ветка `sim` останется как ветка, в которой хранится **шаблон**, на котором можно строить свои алгоритмы. Nav2, PyTorch и все такое добавляйте по необходимости, но в этой ветке их нет и не будет.  

Возможно есть неактуальные комментарии от клода в коде, так что больше внимания уделяйте самому коду, чем комментам. После клода приходилось переписывать часть кода, тк он убивает производительность, тыкая костыли туда, где они не нужны.

Если нужен пример реализации другой машины на похожей карте: [вот репозиторий, на который ориентировался автор этого репозитория](https://github.com/ulstu/robocross.virtual)

Ветка `main` не будет обновляться, пока алгоритм не будет отлажен в симуляции. Основной смысл этого репозитория - автономная езда реального автомобиля Lada Vesta Cross.
